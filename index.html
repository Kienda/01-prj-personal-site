Thirst to Thrive

A story-driven browser adventure for charity: water. Players restore a village water system across six missions, built with vanilla JavaScript and no game engine, canvas, or framework.

JavaScript, Game Logic, Accessibility

Read the full story

What I built

A story-driven browser adventure where you play an explorer helping Village Kumbala restore its broken water system. There are no enemies to fight — progress comes from finding a clean spring, recovering tools, repairing the hand pump, and delivering water to the village. It runs on about 1,000 lines of plain JavaScript with no game engine, canvas, or framework.

Why I built it

I wanted to raise awareness on my college campus and get other students to take part in charity: water. Facts on a page are easy to scroll past, but a game is something students will actually stop and play — and by the end they have worked through what it takes to bring clean water to a village.

Technologies I used

HTML, CSS, and vanilla JavaScript. No dependencies, no build step. The interface uses real DOM elements with ARIA labels so the game stays accessible, and it supports both keyboard controls and on-screen buttons for phones.

What I learned

I learned how to manage state in a program that never stops running. A game has to track where the player is, which mission is active, and what they are carrying — all at the same time — and every one of those has to stay in sync. I also learned that building for a phone is not the same as making the layout smaller: a keyboard-only design is unplayable on a touch screen, so I had to add a direction pad and an interact button.

L'Oréal Smart Product Advisor

An AI beauty assistant that recommends products and routines. A Cloudflare Worker proxies the OpenAI API so the key stays server-side, and the chat keeps full conversation memory.

JavaScript, OpenAI API, Cloudflare Workers

Read the full story

What I built

An AI beauty advisor that answers questions about L'Oréal products and builds personalized routines. It remembers what you tell it across the whole conversation, so you can mention your hair type once and it stays relevant.

Why I built it

L'Oréal wanted to show what AI could do for product discovery. I wanted to find out how a real AI model actually gets connected to a normal web page.

Technologies I used

JavaScript, the OpenAI API, and a Cloudflare Worker I wrote and deployed myself. HTML and CSS for the interface.

What I learned

This is the project where API integration finally clicked for me. I learned that an API key can never live in frontend JavaScript, because anyone can open the browser and read it — so I deployed a Cloudflare Worker to hold the key and pass my requests through to OpenAI. I also learned that a chatbot has no memory by default: it forgot everything between messages until I started sending the full conversation history with every request. Once I understood this pattern, I could connect to any API.

NASA Space Explorer

An app that fetches NASA's Astronomy Picture of the Day over any date range and renders a gallery of images and videos with a keyboard-accessible detail modal.

JavaScript, NASA API, Async Fetch

Read the full story

What I built

An app that pulls NASA's Astronomy Picture of the Day for any date range you choose and displays the results as a gallery, with a detail view you can open for each entry using the mouse or the keyboard.

Why I built it

After the L'Oréal chatbot I wanted to prove the API skill was real and not one lucky project, so I connected to a completely different API from a completely different organization.

Technologies I used

JavaScript with async fetch, NASA's public APOD API, HTML and CSS.

What I learned

This confirmed that API integration is a repeatable skill: read the documentation, build the request, handle the response. The new lesson was judgment about keys. NASA's key is free and rate-limited and the browser calls NASA directly, so the key is public no matter where I put it — the opposite of the L'Oréal project, where the key had to be hidden behind a server. Knowing which situation you are in is the real skill. I also learned that live data is messy: some days return a video instead of an image, so I wrote a separate path for those instead of letting them break the gallery.

Intel Sustainability Timeline

A responsive interactive timeline of Intel's sustainability milestones, with hover transitions, an audited accessibility pass, and automatic right-to-left layout for translated pages.

HTML, CSS, JavaScript, Accessibility

Read the full story

What I built

An interactive timeline of Intel's sustainability milestones that adapts to desktop and mobile, and automatically flips its entire layout to right-to-left when the page is translated into Arabic, Hebrew, Persian, or Urdu. It scores 100 out of 100 on the Lighthouse accessibility audit.

Why I built it

The assignment was a responsive timeline. I added language direction support because a timeline reads in one direction by design, and I realized that if someone translated the page into Arabic the whole layout would fall apart.

Technologies I used

HTML, CSS, and JavaScript, using a MutationObserver to watch for language changes after the page loads. Lighthouse for accessibility testing.

What I learned

I learned to plan a layout before building it, not after. A language like Arabic is written right to left, so without planning for it the UI gets messed up — the timeline flows the wrong way and the text alignment fights the content. I detect direction three ways: the page's language tag, the CSS classes translation tools add, and as a last resort by counting how many Arabic or Hebrew characters are actually on the page. The hardest part to figure out was that translation happens after the page has already loaded, so I had to watch for changes and re-apply the direction instead of checking only once at startup.
